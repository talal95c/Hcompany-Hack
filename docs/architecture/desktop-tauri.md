# Desktop Tauri v2
## Fenêtres
Rust possède deux fenêtres transparentes toujours au premier plan : guide (pointeur, ✓) toujours click-through ; pill (état, commandes) click-through sauf au survol de sa zone interactive. setIgnoreCursorEvents s'applique à toute la fenêtre, pas à une forme CSS. Il faut donc deux fenêtres et un mécanisme natif de suivi de position pour activer la pill avant que la WebView ne puisse recevoir le survol ; ne pas dépendre seulement de mouseenter d'une fenêtre qui ignore les événements. Ce mécanisme est un risque M1 à valider.
Transparence macOS : activer macOSPrivateApi ; implication distribution/signature à examiner avant diffusion. Web affiche seulement pointer, pill, ✓ et état des permissions.
## Capture et confidentialité
ScreenCaptureKit sélectionne la fenêtre Blender et exclut explicitement nos fenêtres via filtre d'application/fenêtres. setContentProtected est une défense supplémentaire, pas la solution : macOS 15+ ScreenCaptureKit ignore la protection de contenu. Vérifier par une capture réelle avec le pointeur visible à l'écran mais absent de l'image envoyée. Aucun écran complet envoyé par défaut ; recadrage sur la région demandée et accord utilisateur.
## IPC et cycle de vie
Web → Rust : permission.status, permission.request, capture.region, input.action, sidecar.start/stop. Rust → web : permission.changed, capture.result, input.result, sidecar.status. Le contrat [WebSocket](../contrats/ws-desktop.md) relie desktop à engine ; les clés cloud restent côté engine, jamais dans la WebView.
Rust lance un seul sidecar Python, lui transmet adresse locale et jeton éphémère sans journalisation, attend ready, puis connecte les clients. Quitter : annuler actions, relâcher touches, fermer sockets, arrêter le sidecar ; arrêt forcé seulement après délai de grâce de 3 s (est.). Un crash propose un redémarrage avec snapshot, sans reprise aveugle d'injection.
## Permissions et entrée
Plugin global-shortcut pour push-to-talk, raccourci configurable et conflit visible. Permissions Screen Recording, Accessibility, Microphone présentées séparément avec explication et vérification réelle. Un refus garde le mode texte/checks. Tester la capture après accord ; un redémarrage peut être nécessaire. La capture micro native ou WKWebView reste à arbitrer après essai de permission.
enigo injecte souris/clavier uniquement pendant une session « fais-le » explicitement autorisée et si Blender a le focus. Une action par tour Holo, nouvelle capture après action, stop global prioritaire, relâchement garanti des touches. Aucun mot de passe ou raccourci système destructif automatisé.
## Retina et DPI
Repères : coordonnées Blender régionales (origine bas-gauche), crop en pixels physiques (origine haut-gauche), sortie Holo normalisée [0,1000], bureau logique et CSS.
Pour crop physique (cx, cy, w, h), point normalisé (u,v) : px=cx+u*w/1000 ; py=cy+v*h/1000. Puis logique écran = origine logique moniteur + (point physique - origine physique moniteur)/scale. Borner au dernier pixel et à la région ; inverser Y une seule fois lors de la conversion Blender. Ne pas diviser deux fois par scale. Une capture redimensionnée garde sa transformation inverse. Multi-moniteur : échelles par moniteur, origine parfois négative ; suspendre la cible si le crop chevauche une frontière non gérée.
## Windows
Graphics Capture remplace ScreenCaptureKit ; DPI awareness et échelle par moniteur ; mécanisme d'exclusion natif à vérifier, pas une garantie documentaire. Pas de permission Accessibility macOS, mais limites d'injection sur fenêtres élevées. Backend enigo partagé, tests natifs séparés ; le packaging Windows n'est pas un objectif de la démo.
